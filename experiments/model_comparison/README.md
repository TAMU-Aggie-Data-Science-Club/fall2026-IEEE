# Model comparison: beating the Alliander baseline

Follow-up to the [Alliander experiment](../alliander/README.md). Same data, same 60 s / 300 s hot-spot targets, same held-out rows (scenarios S031-S036, one forecast every 30 s), so the numbers are directly comparable.

## Recorded result

Mean absolute error in degrees C; smaller is better. "CV" is 5-fold cross-validation over the 30 train+val scenarios, holding whole scenarios out together. Models were chosen on CV; the test column was scored afterwards.

| Model | CV 60 s | CV 300 s | Test 60 s | Test 300 s |
|---|---|---|---|---|
| **GRU correcting the RC forecast** (3-seed mean) | **0.233** | **1.666** | **0.244** | **1.897** |
| XGBoost + episode clock | 0.235 | 1.905 | 0.283 | 2.091 |
| XGBoost on lag features | 0.241 | 1.976 | 0.302 | 2.162 |
| Calibrated first-order RC | 0.405 | 2.540 | 0.435 | 2.703 |
| Persistence | 1.025 | 4.408 | 1.007 | 4.395 |
| Alliander (earlier experiment) | n/a | n/a | 0.919 | 4.815 |

The GRU cuts test error by **73% at 60 s and 61% at 300 s** relative to Alliander, and beats persistence at both horizons. Test RMSE is 0.613 C and 4.335 C (Alliander: 1.400 C and 6.716 C).

Even the two-parameter RC model halves Alliander's error. The data were generated by a first-order RC equation, so a model with that structure fits where an oil-immersed transformer model does not.

## What limits accuracy

Almost all remaining error comes from forecast windows in which the load steps *after* the forecast is issued. Test MAE for the GRU:

| | No load step in window | Load step in window |
|---|---|---|
| 60 s | 0.17 C | 2.82 C |
| 300 s | 0.86 C | 8.40 C |

No model sees the future load, so those windows are close to a floor. Hyperparameter tuning, deeper trees, Kalman-filtered temperature, and blends all moved CV by less than the spread between GRU random seeds (1.65-1.87 C at 300 s), which is why the GRU averages three seeds. Further gains need information about future load (a schedule or a load forecast), not a better regressor.

## Caveats

- **Learned models partly memorise the generator's script.** Overloads in these scenarios start 265-485 s into an episode, last roughly 900-1,400 s, and cycle 480 s on / 240 s off. The step-timing features and the GRU pick this up. `xgb_clock` goes further by reading elapsed time directly; it is reported only to show the size of that effect. None of this timing skill should be expected on real hardware.
- **Trees do not extrapolate.** Test scenario S033 reaches 109 C; no training scenario exceeds 94 C. XGBoost's 300 s error there is 5.1 C versus 3.3 C for the GRU and 4.2 C for RC. The RC model is the safest choice outside the training range.
- Everything in the Alliander README about synthetic data, overlapping windows, and six test scenarios being the real sample size applies here too.

## Run it

Uses the same local CSVs as the Alliander experiment (see [the source register](../../DATA.md)).

```sh
python -m pip install -r experiments/model_comparison/requirements.txt
python -m unittest discover -s experiments/model_comparison -p 'test_*.py' -v
python experiments/model_comparison/compare.py          # RC + XGBoost, under 1 minute
python experiments/model_comparison/compare.py --gru    # adds the GRU, about 15 minutes, needs torch
```

The Alliander column appears when `data/processed/alliander/predictions.csv` exists from the earlier experiment. Outputs go to ignored `data/processed/model_comparison/`: `metrics.csv`, `per_type_metrics.csv`, `load_step_metrics.csv`, `predictions.csv`, `results.json`.

## The models

All inputs are readings at or before the forecast time; a test checks that changing future rows leaves features unchanged.

- **RC**: `T(t+h) = T_eq + (T - T_eq) * exp(-h / tau)` with `T_eq = ambient + R * power`, holding power and ambient at their current values. `tau` and `R` are fitted per rail with a robust loss (fitted: tau 378-464 s, R 2.9-3.1 C/W).
- **XGBoost**: predicts the temperature change from 5 s mean temperature, power means over 5-300 s, temperature and power changes over 30-300 s, the RC forecast, and time since / count of detected load steps (a >5 W jump).
- **GRU**: reads the last 300 s of temperature, power and ambient at 5 s steps plus the same step-timing features, and predicts a correction to the RC forecast, so it falls back to physics where it has learned nothing.

Also tried and not kept: ridge regression, extra-trees, sklearn histogram boosting, a 1-D CNN, and RC/tree/GRU blends. None beat the GRU on CV.
